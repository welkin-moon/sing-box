# 自适应多路径系统：模块边界与交付顺序

sing-box 负责数据转发；独立 Go 控制面负责测量、决策和执行协调。
Windows x64、Android arm64 与 Debian 12 共享策略模型，通过各平台适配器执行网络操作。
公开仓库只保存实现、Schema 和虚构示例；真实节点目录、订阅、密钥和测量中的敏感标识保存在部署侧。

## 优先级

1. **BBR 与入口／中继之间的双向基线优化优先。** 先保存内核、拥塞算法、队列与实际吞吐记录，
   再比较 CUBIC、BBR。分别报告每个方向及完整路径，不能把启用 BBR 等同于吞吐提升。
2. 完成当前原生双通道的 Windows／Android 可用性与真实链路验证。
3. 在已有 `model`、`engine`、`control` 上扩展有向路径评分与带宽控制，不另造相互冲突的控制器。
4. 再接入 TCP Brutal／HY2 调速、自动中继组合、热备与可恢复传输。

## 必须区分的对象

| 对象 | 内容 | 测量约束 |
| --- | --- | --- |
| 物理网络 | 当前接入网络、地址族、计费与电量状态 | 网络切换后隔离历史，避免混用 Wi-Fi 与蜂窝测量 |
| 有向链路 | 起点、终点、协议、方向、拥塞控制 | 上下行与 IPv4／IPv6 分开记录 |
| 完整路径 | 有序中继、最终出口、目标业务 | 必须端到端验证，不能累加单段分数冒充实测 |
| 分离会话 | 上传路径、下载路径、共同汇合服务 | 共同出口 IP 之外，还要共享经过鉴权的会话状态 |

## 可选模块与接口约束

- **观测器**：产出带时间和网络标识的测量；区分 DNS、TLS、连接、HTTP 状态和实际业务失败。
  URL Test 仅为其中一个信号；登录页 HTTP 200 不能代表登录或业务操作成功。
- **路径规划器**：基于有向图生成少量无环候选，保留节点能力与协议兼容约束，交给端到端观测器验收。
- **评分器**：综合有效吞吐、p95 延迟、丢包／重传、稳定性、资源和流量成本，输出解释与置信度。
  低业务流量不等于容量不足；没有饱和或拥塞证据时不据此降速。
- **带宽控制器**：给出有上下限的建议，执行器先验证平台能力。TCP Brutal 的内核模块与连接组管理
  仅在支持的 Linux 部署启用；禁止用覆盖整个客户端 IP 的规则误伤 SSH 或其他服务。
- **执行器**：普通路径使用 selector／detour；HY2 暂按新连接启用新参数、旧连接排空设计，
  不假设已有通用热更新接口。TCP Brutal 的实时组调速接入前需要独立验证。
- **双通道传输**：`bond` 已独立于 XHTTP；两条外层连接均由客户端建立，在同一 Hub 汇合。
  当前支持 TCP 字节流、有限缓冲、反压、半关闭、鉴权与重放防护；UDP、透明恢复与跨实例汇合仍待实现。
- **平台与 Agent**：Android 使用 VPN 生命周期和受保护的套接字；Windows 处理网络切换与休眠；
  Debian Agent 使用有边界的权限、资源锁、配置检查和超时回滚。协调服务离线不能阻断已知可用路径。

每个自动模块都需要独立开关。手动选择及手动速率覆盖优先，自动控制器不得悄悄改写它们。
部署变更不得依赖重启整个 TUN／核心来完成普通选路；独立管理通道始终保留。

## 调参起点（设计参数，尚非已验证最优值）

被动采样 10–30 秒，普通决策 2–5 分钟，空闲深测 30–60 分钟；升速每轮 5–10%，
有拥塞证据时降速 15–25%。候选路径持续优于当前约 15% 后才考虑切换，并结合保持时间和失败恢复计数。
主动测速需设置单次字节、总流量、并发、计费网络与电量预算；默认不能持续跑满网络。

## 当前状态

已有控制面提供 HTTPS／下载探测、连续失败与恢复计数、保持时间、selector 读回与失败恢复，
并有 GUI、CLI、TUI、MCP 接口。`bond` 提供独立上传／下载配置档及已有 detour 链的编译和会话层。
Android 构建与桌面导出分开：Android 生成 TUN 和默认 TCP DoH，保留用户导入的 DNS；桌面保留本地 mixed 入口。

完整有向图规划、多维评分、自动容量发现、Brutal 动态调速、跨平台网络画像和统一 Agent
尚未集成为已发布功能。编译成功不能替代 Android 真机 VPN、长期稳定性和业务可用性验收。
